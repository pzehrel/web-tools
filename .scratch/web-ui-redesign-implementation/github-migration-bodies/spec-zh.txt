# Web UI 重设计实施规格

## 问题陈述

现有工具界面无法提供高频开发与设计工作所需的紧凑、一致的工作空间。导航、间距、控件、反馈和画布组织需要完整重设计。早期经过简化的原型也使既有能力难以辨认，造成正式实现时丢失重要功能的风险。

用户已完成当前 F 原型的评审。正式实现必须在采用已确认布局和共享语义色系统的同时，保留四个公开工具的完整行为。已评审原型是设计依据，不是生产实现，也不能证明全部运行行为已通过验收。

## 解决方案

将已评审的首页、URL 与二维码、帧动画、Lottie 预览和点九图实现为正式界面。采用紧凑控件、直接导航、默认可见的画布、按任务组织的浮动控件，以及一致的亮暗语义色。保留现有解析、图片处理、渲染、导出、记录与兼容行为。

首页和工具切换只展示四个公开工具。CSS 扫光与字体工具箱继续暂缓，没有可见导航入口，既有直达路由和功能保留。应用继续采用浏览器形态，保留现有存储与 SSG 架构，不以宣传方式强调数据位置或上传行为。

## 用户故事

### 共享行为

1. 作为高频用户，我希望首页展示四个 ready 公开工具，以便直接进入任务，并让隐藏工具继续隐藏。（G01）
2. 作为回访用户，我希望现有路由、旧 URL／二维码重定向、隐藏工具直达路由与未知地址回退继续有效，以便已有链接仍可使用。（G02）
3. 作为工具用户，我希望左侧有易发现的返回首页操作，并可切换公开工具，以便导航不占用常驻侧栏。（G03）
4. 作为工具用户，我希望跟随系统、浅色、深色偏好持久保留，响应系统变化并在首屏绘制前生效，以便主题行为保持一致。（G04）
5. 作为项目用户，我希望使用正确的 GitHub 仓库图标并在新标签页打开链接，以便可靠地访问项目。（G05）
6. 作为回访用户，我希望记录身份、载荷、元数据与旧数据转换保持兼容，以便重设计后仍能找到已保存的工作。（G06）
7. 作为图像工具用户，我希望共享查看手势、边界／背景控件及编辑保护，以便查看与编辑不会相互干扰。（G07）
8. 作为访问者，我希望静态路由内容、逐页元数据和唯一的水合界面正确，以便页面能够正确加载并被索引。（G08）
9. 作为 Safari 网页应用用户，我希望保留现有 manifest、图标和独立窗口元数据，以便浏览器应用继续正确启动。（G09）

### 已评审的界面决策

10. 作为高频用户，我希望间距紧凑且画布默认可见，以便有效工作内容占据可用屏幕。（D01）
11. 作为画布工具用户，我希望窄任务控件位于画布旁、查看控件浮动显示，以便参数靠近正在处理的内容。（D02）
12. 作为工具用户，我希望纯图标操作没有可见描边，同时保留悬停、选中、禁用和键盘焦点反馈，以便控件紧凑且易理解。（D03）
13. 作为工具用户，我希望亮暗主题均有蓝色主色、浅蓝次要色，以及明确的成功、失败、警告和提示色，以便层级与反馈清楚。（D04）
14. 作为 URL 工具用户，我希望顶部输入区和二维码区同排等高，下方参数树独占整行，再下方记录独占整行，以便各区域位置明确。（D05）
15. 作为 URL 工具用户，我希望树 item 上下间距紧凑，并保留换行与编辑字段，以便高效阅读长参数树。（D06）
16. 作为帧动画用户，我希望帧序列横贯整个底部，短进度控件紧邻其上，以便保留有用的画布空间。（D07）
17. 作为帧动画用户，我希望进度定位独立于缩略图选择，且缩略图不随播放高亮，以便序列编辑保持视觉稳定。（D08）
18. 作为 Lottie 用户，我希望使用图集优化、播放设置和项目记录标签，并常驻资源对比与导出，以便切换任务时保留结果上下文。（D09）
19. 作为 Lottie 用户，我希望使用窄左栏、短播放控件和独立浮动图集预览，以便动画仍是主要工作区。（D10）
20. 作为点九图用户，我希望中心裁剪靠上，并可移动和调整拉伸预览 HUD 的大小，以便方便地执行高频裁剪和预览比较。（D11）
21. 作为点九图用户，我希望分别重置源图视图、预览视图和 HUD，以便恢复查看状态不会意外改变输出参数。（D12）

### URL 与二维码

22. 作为开发者，我希望解析协议、路径、查询文本、嵌套编码 URL 和 hash 路由，并保留重复 key、无值字段、空值及错误转义容错，以便编辑真实链接。（U01）
23. 作为开发者，我希望使用显示各 URL base 的递归可编辑参数／hash 树，以便看清嵌套结构。（U02）
24. 作为开发者，我希望编辑 key、普通 value、根及嵌套 base 时正确重建子树并保留后缀，以便保留无关参数。（U03）
25. 作为开发者，我希望 Enter／失焦提交、Escape 取消、无变化编辑不改写内容，并在新增 key 时自动聚焦，以便行内编辑可预期。（U04）
26. 作为开发者，我希望在根级新增、普通字段之后插入，以及嵌套 URL 内新增，以便在正确层级添加字段。（U05）
27. 作为开发者，我希望删除字段或 URL 子树前确认，以便取消时保留当前输入。（U06）
28. 作为开发者，我希望将 key／hash 节点和整棵子树移到有效目标，并拒绝无效、自身或后代投放，以便安全调整结构。（U07）
29. 作为开发者，我希望分别复制原始输入和序列化的根／子树 URL 并获得反馈，以便选择合适的完整表示。（U08）
30. 作为开发者，我希望合法的 `$$name` 变量生成带高亮、编码层数正确且可复制的 JavaScript 模板代码，以便复用嵌套 URL 模板。（U09）
31. 作为工具用户，我希望明确载入嵌套 OAuth 示例，以便在探索工具时不自动替换初始空态。（U10）
32. 作为工具用户，我希望 URL 或纯文本在防抖后生成现有二维码 PNG，忽略过期结果并正确响应清空，以便二维码对应当前内容。（U11）
33. 作为工具用户，我希望选择图片、拖入二维码区、在文本输入外粘贴图片都能识别二维码，并支持重复选择同一文件，以便全部既有识别路径可用。（U12）
34. 作为工具用户，我希望区分图片不可读与未发现二维码，失败不破坏当前文本，并获得纯文本树说明，以便从不合适的输入中恢复。（U13）
35. 作为工具用户，我希望点击二维码图片打开包含只读参数树的放大预览，并可通过 Escape／遮罩关闭，以便检查结果。（U14）
36. 作为工具用户，我希望页面下载操作直接下载纯二维码 PNG，以便一次操作完成常用导出。（U15）
37. 作为工具用户，我希望放大预览的下载操作对 URL 内容直接生成现有二维码与参数图，以便分享完整结构化结果。（U16）
38. 作为工具用户，我希望直接导出保留可用性判断、忙碌保护、错误反馈与纯文本二维码回退，并取消下拉菜单，以便已评审下载流程可靠。（U17）
39. 作为回访用户，我希望保存新增有名快照，更新选中记录需明确操作，以便打字不静默覆盖已保存内容。（U18）
40. 作为回访用户，我希望保留默认记录名回退与 Enter／失焦／Escape 重命名语义，以便命名行为可预期。（U19）
41. 作为回访用户，我希望选中记录载入输入，再次选中则取消选择而不覆盖输入，以便选择与编辑相互区分。（U20）
42. 作为回访用户，我希望桌面记录提示与手机预览弹窗显示二维码／树或纯文本，以便选择前检查记录。（U21）
43. 作为回访用户，我希望复制记录、确认单条删除、确认全部清空，并正确清理选中状态，以便记录管理完整。（U22）
44. 作为回访用户，我希望持久记录和旧 URL／二维码记录继续在原存储身份下恢复，读取失败不阻断工具，以便升级后保留工作。（U23）
45. 作为开发者，我希望恢复当前、旧 text 和裸分享 hash，保留防抖替换地址与清空，以便分享链接有效且打字不增加历史条目。（U24）
46. 作为工具用户，我希望没有分享内容时输入、树与二维码均显示空态，以便诚实地开始工作，并自主使用示例。（U25）

### 帧动画

47. 作为设计者，我希望通过选择或画布拖放导入多张浏览器可解码图片，并跳过无效图片，以便有效帧仍可使用。（F01）
48. 作为设计者，我希望 ZIP 与目录导入保留现有支持格式、源文件名和归档过滤，以便加载已有素材集合。（F02）
49. 作为设计者，我希望新批次按自然文件名顺序追加，同时保留既有手动顺序，并可主动全局排序，以便自主组织序列。（F03）
50. 作为设计者，我希望明确载入示例，以便无需提供文件也可预览与导出。（F04）
51. 作为设计者，我希望逐帧、全选／全不选控制预览、播放和导出，但不删除素材，以便可逆地调整参与帧。（F05）
52. 作为设计者，我希望保留缩略图、文件名、原尺寸／字节数、前后拖排与稳定的选中反馈，以便整理帧时不受播放高亮干扰。（F06）
53. 作为设计者，我希望共同透明边裁剪包含叠放预览、边界、实时 alpha 控制、混合尺寸警告、取消／应用和结果反馈，以便有依据地裁剪。（F07）
54. 作为设计者，我希望保留播放、暂停、步进、已选缩略图定位和既有快捷键，并保护文本输入、支持 Escape 关闭裁剪弹窗，以便高效操作。（F08）
55. 作为设计者，我希望保留 FPS 与时长关系、小数反推和时间信息，以便预览与导出的时序一致。（F09）
56. 作为设计者，我希望使用含端点的起止范围、完整范围重置和随勾选收敛的范围，以便播放与导出使用预期帧。（F10）
57. 作为设计者，我希望正序、倒序、往返支持无限或有限循环，并在结束后可重播，以便播放和代码保留选定行为。（F11）
58. 作为设计者，我希望自动按源尺寸适配，并支持缩放／捏合、平移、倍率反馈与重置，以便检查大小不同的帧。（F12）
59. 作为设计者，我希望使用边界与随主题变化的棋盘／纯色查看背景，以便检查透明度且不改变输出像素。（F13）
60. 作为设计者，我希望像素风设置作用于预览和生成样式，以便像素素材保留预期渲染效果。（F14）
61. 作为设计者，我希望 PNG 精灵图使用源图最大单格尺寸，小帧居中并联动行列设置，以便导出像素与布局正确。（F15）
62. 作为设计者，我希望看到实时精灵图预览、帧／单格／网格／输出尺寸及空白／忙碌状态，以便检查真实导出排列。（F16）
63. 作为开发者，我希望保留 CSS／Less／SCSS 输出、变量与相对尺寸选项、匹配的方向／循环／时长／像素风、复制反馈及代码区全选，以便复用生成的动画。（F17）
64. 作为回访用户，我希望有名持久项目恢复字节、顺序、勾选、范围、播放、裁剪阈值和导出设置，并可加载／删除，以便准确续接工作。（F18）
65. 作为设计者，我希望清空素材停止播放，并重置相关勾选、范围、裁剪与导入反馈，以便干净地开始下个项目。（F19）
66. 作为设计者，我希望空勾选、归档／导入、裁剪、导出和复制都有合适的忙碌／禁用反馈，以便理解失败与不可用操作。（F20）

### Lottie

67. 作为设计者，我希望通过单个 ZIP 或完整目录导入项目，保留路径且要求恰有一个有效 data.json，以便支持的项目打包方式明确。（L01）
68. 作为设计者，我希望按现有格式解析嵌套／预合成、相对路径和内嵌图片引用，并提示缺失／不可读素材，以便项目资源正确且不自动获取远程图片。（L02）
69. 作为设计者，我希望示例、替换和清空重置项目相关的优化、播放与查看状态，以便项目之间不泄漏状态。（L03）
70. 作为设计者，我希望保留两种既有 Lottie 渲染库及 canvas／SVG 渲染器，以便比较受支持的引擎。（L04）
71. 作为设计者，我希望选择完整显示和铺满裁切，以便动画适合目标查看区域。（L05）
72. 作为设计者，我希望播放、暂停及小数帧定位保留当前／总帧和项目元数据，以便精确检查动画时序。（L06）
73. 作为设计者，我希望保留既有速度挡位、方向和循环，以便灵活检查播放。（L07）
74. 作为设计者，我希望主画布自动适配，并独立支持缩放／捏合、平移、倍率反馈和重置，以便检查完整动画。（L08）
75. 作为设计者，我希望动画和图集都支持边界与随主题变化的棋盘／纯色背景，以便看清透明素材。（L09）
76. 作为设计者，我希望可开关优化，改变选项后自动重建，重建或关闭时使用原素材，以便预览始终表示有效的当前状态。（L10）
77. 作为设计者，我希望保留图集最大尺寸、间距和边缘扩展及其默认值和范围，以便打包控制完整。（L11）
78. 作为设计者，我希望保留旋转、保持动画位置的裁透明边与相同像素合并，以便继续使用既有优化选项。（L12）
79. 作为设计者，我希望可调整高级的二次幂、正方形图集和 alpha 阈值，以便设置详细图集约束。（L13）
80. 作为设计者，我希望检测受支持的动态图片、将其排除于图集打包并说明，以便优化不会把动态资源变成静态。（L14）
81. 作为设计者，我希望对比前后字节、纹理数、像素与估算 RGBA 内存，标明增加，并查看占用率和去重统计，以便评估真实结果。（L15）
82. 作为设计者，我希望查看单张／多张图集，并独立适配、缩放／捏合、平移、显示倍率、边界和重置，以便不干扰主动画。（L16）
83. 作为设计者，我希望优化 ZIP 保留改写 data.json、编号图集 PNG 和必要的原始不可优化素材，以便导出项目仍可使用。（L17）
84. 作为回访用户，我希望有名持久完整项目恢复优化、渲染库、渲染器、循环、速度、方向与适配设置，并可加载／删除，以便继续检查。（L18）
85. 作为设计者，我希望看到可滚动的错误／警告、缺失素材详情、操作／引擎失败，以及忙碌／空白／禁用状态，以便理解问题并恢复。（L19）
86. 作为手机用户，我希望能访问堆叠或标签式控件、换行动作、双画布触屏手势及可滚动消息，以便完成 Lottie 核心任务。（L20）

### 点九图

87. 作为设计者，我希望通过选择图片或拖入首个文件开始编辑，并显示名称和源尺寸，以便对预期图片切片。（N01）
88. 作为设计者，我希望取消选择保留当前图片、区分类型与解码错误、有效替换清除错误，以便导入恢复可预期。（N02）
89. 作为设计者，我希望生成示例走正常载入／默认参数流程，以便示例反映真实工作方式。（N03）
90. 作为设计者，我希望替换图片时恢复既有的图像推导切片／宽度、外扩与裁剪默认值并重新适配源图，以便旧几何不破坏新图。（N04）
91. 作为设计者，我希望清除图片回到导入态并移除导入／裁剪反馈，以便工作区一致地重置。（N05）
92. 作为设计者，我希望四边切片以非负整数源像素表示，并根据对边与恢复后尺寸规范化，以便切线不能交叉。（N06）
93. 作为设计者，我希望切线拖动通过指针捕获、当前缩放换算源像素并处理结束／取消，以便数值与切线同步。（N07）
94. 作为键盘用户，我希望切线是具有范围的可聚焦 slider，支持方向键 1 像素／Shift 10 像素调整，以便不依赖拖动也能精确切片。（N08）
95. 作为设计者，我希望切片重置恢复图像推导默认值而不改无关参数，以便局部重置安全。（N09）

## 实现决策

### 范围与依据

- 实现首页、共享界面与四个公开工具：URL 与二维码、帧动画、Lottie 预览、点九图。中文界面统一使用“URL 与二维码”，保留已确认的 F 首页顺序和直达工具的组织方式。
- 最终已评审 F 行为与功能保留验收共同定义结果。历史“原型缺失”不授权省略能力。保留 U01–U25、F01–F20、L01–L20、N01–N29、G01–G09，仅服从下文明确列出的覆盖决定：本轮共 103 组既有功能。
- D01–D12 表示已评审界面决策，不是新增历史功能组。115 条用户故事覆盖这两类要求。
- 复用现有解析、二维码编解码、图片／裁剪计算、动画引擎、图集优化、归档、资源指标和存储契约。依据这些契约实现可维护的生产组件，原型作为独立设计参照保留。
- 保留用户无关改动。本规格不授权发版、部署、自动提交或破坏性清理。

### 共享界面与颜色

- 保留紧凑页头、易辨认标题、左侧返回、仅公开工具的切换菜单、正确的 GitHub 图标／链接和三种主题选择。导航不采用常驻的后台管理侧栏。
- 导航菜单位于浮动画布控件之上，激活的模态框位于页头之上。页头与画布控件对齐，弹出层约束在视口内，避免控件重叠或被遮挡。
- 主要、次要、描边、幽灵和危险操作使用现有语义组件约定。纯图标操作没有可见边框，保留悬停、选中、禁用和焦点反馈。主题按钮保持等大的方形、图标居中及浅色选中填充。
- 将已评审的蓝色主色、浅蓝次要色、绿色成功、红色失败、琥珀警告和青蓝提示色板应用到正式亮暗主题。原始色值集中管理，组件使用语义样式。最终界面不能依赖开发专用色板开关。
- 状态文字／图标与颜色同时存在。复制确认后可短暂将主操作改为可读的成功填充。依据明确状态分类，不根据翻译后的文案子串判断。非致命警告和无需处理的提示结果要区别于失败。
- 保留紧凑控件以及无装饰阴影／悬停位移的规则。对于重设计的公开界面，已评审的语义色、紧凑布局、浮动任务面板规则优先于冲突的旧单色、单一色相和宽松表单规则。正式实现时记录协调后的生产设计规范。
- 桌面工作面板保持窄幅，参数宽度约为原型的 240px，必要时内部滚动。手机通过已评审的标签／堆叠访问导入、核心参数、预览、输出和记录；精细切片、多帧排序优先优化桌面，但不从手机删除。

### URL 与二维码布局和导出

- 桌面输入和二维码面板共用首行并等高，二维码居中。可编辑树独占第二行，记录独占第三行。紧凑／手机宽度下纵向排列全部区域，不发生整页横向溢出。
- 保留真正的递归可编辑树及祖先连接线，不新增独立的平面解析结果摘要。收紧对象是 item 间距，而非标题或板块外围：普通行保留已评审的 20px 最小高度，根行 24px，编辑行允许撑高。长值换行或可在树的滚动区访问，操作仍可用。
- 原文复制与序列化根／子树复制相互区分。保留所有插入位置、无效投放保护、删除确认、变量及条件出现的代码复制。
- 保留 320px、纠错级别 L 的二维码 PNG、400ms 防抖和过期结果保护。页面下载纯二维码；放大弹窗对 URL 直接下载现有组合图，对纯文本回退为纯二维码。按用户明确决定移除下载下拉及其菜单专用关闭行为，同时保留可用性、忙碌保护、可重试错误和两种导出格式。
- 保留组合图几何：宽 1400px、二维码 500px、树文本换行、最多绘制 300 行及省略提示。保留现有输出命名与编码行为。
- 保存始终新增快照。更新选中记录仍需明确操作，打字不覆盖保存内容。保留命名、预览、选择／取消选择及重命名／删除语义。
- 保留当前、旧 text 与裸分享 hash、防抖替换历史及清空。没有分享内容时默认为空，OAuth 示例由用户明确载入。

### 帧动画工作台

- 使用已评审的窄左参数面板、主画布、全宽底部序列及紧邻其上的短浮动播放／进度控件。序列覆盖左侧面板所在宽度；折叠后释放画布空间，控件始终可达。
- 播放进度保持可见和可定位。定位暂停播放，可检查任意已选帧，不改写配置的播放／导出范围；继续播放遵守该范围。
- F06 的明确覆盖决定：移除随播放变化的缩略图高亮及自动跟随。保留用户选择、焦点、投放目标、缩略图、元数据、排序与点击暂停／定位。当前帧仍可通过进度控件辨认。
- 保留追加／自然排序、勾选、共同透明边裁剪及完整导出选项。PNG 精灵图保持源图推导分辨率、小帧居中、行列联动，并保留 CSS／Less／SCSS 生成。不引入 GIF／视频导出器。
- 保留默认值和范围：初始 12 FPS，滑块 1–60，数字输入 1–120 并支持由时长反推的小数，含端点的播放／导出范围，正序／倒序／往返，以及无限或 1–999 次循环。保留既有裁剪 alpha 阈值和重置／错误行为。

### Lottie 工作台

- 使用已评审的窄左任务面板，分为图集优化、播放设置、项目记录。资源对比与主要 ZIP 导出在任务内容下方保持可达。切换标签保留编辑状态与焦点行为。
- 项目导入／元数据与查看控件组织在共享顶部工具条；画布保留短播放控件，图集使用独立浮动预览。可滚动素材消息位于参数面板底部，失败详情适当展开，手机有易发现的消息入口。
- 保留 ZIP／目录导入约束、全部既有资源解析及两种渲染库／渲染器。不新增远程图片自动抓取或不受支持的散装 JSON 导入。
- 保留 0.01 帧步长的小数定位、既有速度挡位、方向、循环和适配模式。定位暂停播放，主视图与图集视图保持独立。
- 保留打包设置／默认值：最大尺寸 1024／2048／4096；间距 0–32、默认 2；边缘扩展 0–8、默认 1；旋转关闭、透明裁剪开启、去重开启；高级二次幂与正方形关闭；alpha 阈值 0–255、默认 1。保留动态图片排除和资源增加提示。
- 预览当前有效优化结果，重建或关闭时用原素材；将现有改写动画、编号图集及必要原始素材导出为有效 ZIP。资源指标必须对应同一结果，并清楚区分估算内存与实测文件字节。

### 点九图工作台

- 保留已评审的窄左面板与可见源图画布。参数顺序为切片边距、高频中心裁剪、渲染设置；CSS 和记录可访问，复制、保存与裁剪 PNG 保持可达。
- 使用覆盖式拉伸预览 HUD，初始位于工作区右下，支持标题拖动、八向外框调整、有边界的位置和独立重置。支持键盘移动／调整，处理指针结束／取消／丢失捕获，并在视口变化时收敛位置。
- HUD 几何仅改变观察窗口。内部逻辑拉伸尺寸独立，保留 96–720 × 64–480px、八向逻辑缩边，以及角点 8／Shift 40px 键盘步长。HUD 移动／缩放使用已评审的 8／Shift 32px 步长。HUD 几何与查看变换不进入导出或保存参数。
- 清楚区分源图视图重置、预览视图重置和 HUD 重置。保留源像素切线拖动、1／Shift 10px 键盘增量、无效边缘收敛、图像推导默认值及既有自动分析行为。
- 保留绑定／解绑宽度、0–200px 独立宽度、0–100px 外扩、填充和双轴独立 stretch／repeat／round／space。保留两轴／X／Y 中心裁剪及精确的 1:1 PNG 输出。中心裁剪遮罩和平铺警告保持可见。
- 保留现有基于源图的 border-image 渲染器及分开写／简写 CSS 生成器。中心裁剪是独立像素导出，不声称渲染器已使用重新生成的裁剪位图。CSS 是现有可调用的点九图代码格式，不根据旧元数据推断新增 SCSS／Less／Tailwind 生成器。

### 数据、运行与兼容

- 正式界面继续使用现有 ToolStore、IndexedDB 身份、载荷、Blob 归档、元数据规范化及旧 URL／二维码转换。不使用可清除的原型数据库，也不把其记录迁入产品。这是保留既有兼容，不是新增存储结构或后端迁移。
- 保留各工具记录语义：URL 明确保存快照／更新及确认；帧动画／Lottie 有名完整项目归档；点九图源图字节和参数恢复及单条删除。不静默新增会改变这些契约的删除确认、自动保存或持久化字段。
- 保留三种主题持久化与首屏前应用、对象 URL 清理、异步结果归属和既有忙碌保护。除既有像素风输出设置外，查看背景、缩放／平移、HUD 几何与源图边界显示不得改变输出像素或导出参数。
- 保留显式路由身份、旧路由重定向／回退、SSG 水合数据对齐、逐页 SEO，以及现有浏览器／Safari 网页应用元数据。保留路由兼容垫片与仅客户端存储水合保护。
- 最终生产界面没有原型切换条、variant 依赖、临时记录适配器或开发专用主题要求。独立保留可重现的原型依据，不覆盖用户无关工作区改动。

用户于 2026-10-20 确认：主要通过真实产品页面验证输入、编辑、预览、下载、记录和刷新；复用现有解析、舞台和记录测试；额外检查 SSG 水合、旧记录兼容、亮暗主题与手机操作。

# 01: 首页、导航与正式主题

**交付内容:** 从已评审的紧凑首页进入任意公开工具，在页面左侧返回、切换工具、打开正确的 GitHub 链接，并在真实路由上保留跟随系统／浅色／深色偏好。

**Blocked by:** 无，可立即开始。

**Status:** ready-for-agent

**Labels:** ready-for-agent

**Approval:** 2026-10-20 — human user: 可以

依据：[完整规格](https://github.com/pzehrel/web-tools/issues/1#issuecomment-6285079590)；[来源索引](https://github.com/pzehrel/web-tools/issues/1#issuecomment-6285080955)；[任务索引](https://github.com/pzehrel/web-tools/issues/1#implementation-tickets)；[英文原文](https://github.com/pzehrel/web-tools/issues/2)。

**主要需求:** G01–G05、G08–G09、D01–D04。05、07、09 也必须落实画布上的 D01–D02。

## 验收条件

- [ ] 仅四个公开入口；保留重定向、隐藏直达路由和兜底；菜单与弹窗层级正确；主题按钮等大方形；正式蓝色主色及语义色不依赖开发开关；反馈和焦点清晰；水合后仅一份页面，元信息、manifest 与 Safari 行为正确。
- [ ] 使正式设计规范与已确认决策一致。
- [ ] 各工具工作区尚未迁移时，原功能仍可使用。

## 需求验收清单

- [ ] **G01** — 作为高频用户，我希望首页展示四个 ready 公开工具，以便直接进入任务，并让隐藏工具继续隐藏。
- [ ] **G02** — 作为回访用户，我希望现有路由、旧 URL／二维码重定向、隐藏工具直达路由与未知地址回退继续有效，以便已有链接仍可使用。
- [ ] **G03** — 作为工具用户，我希望左侧有易发现的返回首页操作，并可切换公开工具，以便导航不占用常驻侧栏。
- [ ] **G04** — 作为工具用户，我希望跟随系统、浅色、深色偏好持久保留，响应系统变化并在首屏绘制前生效，以便主题行为保持一致。
- [ ] **G05** — 作为项目用户，我希望使用正确的 GitHub 仓库图标并在新标签页打开链接，以便可靠地访问项目。
- [ ] **G08** — 作为访问者，我希望静态路由内容、逐页元数据和唯一的水合界面正确，以便页面能够正确加载并被索引。
- [ ] **G09** — 作为 Safari 网页应用用户，我希望保留现有 manifest、图标和独立窗口元数据，以便浏览器应用继续正确启动。
- [ ] **D01** — 作为高频用户，我希望间距紧凑且画布默认可见，以便有效工作内容占据可用屏幕。
- [ ] **D02** — 作为画布工具用户，我希望窄任务控件位于画布旁、查看控件浮动显示，以便参数靠近正在处理的内容。
- [ ] **D03** — 作为工具用户，我希望纯图标操作没有可见描边，同时保留悬停、选中、禁用和键盘焦点反馈，以便控件紧凑且易理解。
- [ ] **D04** — 作为工具用户，我希望亮暗主题均有蓝色主色、浅蓝次要色，以及明确的成功、失败、警告和提示色，以便层级与反馈清楚。

- [ ] 保留所分配需求 ID 的全部行为，包括规格中的默认值、边界、特殊情况和失败处理。这里的摘要不能替代详细契约。复用产品引擎和存储契约；原型覆盖不等于产品验收通过。
- [ ] 每张票完成并验证真实页面上的完整操作流程。迁移时，其范围之外的现有控件仍须可用。必要的组件提取包含在相应任务内并保持行为；不单设引擎重写或仅建设基础设施的阶段。
- [ ] 每条流程包含适用的亮暗主题、紧凑桌面布局、键盘与焦点行为、手机核心操作、空态／忙碌／错误反馈及相关模块测试。导出票检查解码后的产物或归档内容。记录票使用隔离测试数据、保留产品存储标识，验证刷新和旧记录。

- [ ] 每张实施票执行要求的 lint、类型检查和构建。记录真实产品页面证据；无法执行的浏览器检查保持待验收，不能以源码检查替代。保留无关改动和原型参考。不包含提交、发版或部署。

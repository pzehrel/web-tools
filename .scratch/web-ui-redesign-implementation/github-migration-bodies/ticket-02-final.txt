# 02: URL recursive editing and share-link round trip

**What to build:** Open an empty or shared URL, inspect and edit every nested level, move/add/delete nodes, copy original or serialized values and generate variable templates in the approved layout.

**Blocked by:** [01 — Home, navigation and production themes](https://github.com/pzehrel/web-tools/issues/2)

**Status:** ready-for-agent

**Labels:** ready-for-agent

**Approval:** 2026-10-20 — human user: 可以

Context: [full specification](https://github.com/pzehrel/web-tools/issues/1); [source index](https://github.com/pzehrel/web-tools/issues/1#issuecomment-6285080234); [ticket index](https://github.com/pzehrel/web-tools/issues/1#implementation-tickets); [Chinese translation](https://github.com/pzehrel/web-tools/issues/3#issuecomment-6285082912).

**Primary requirements:** U01–U10, U24–U25, D05–D06.

## Acceptance criteria

- [ ] Equal-height input/centered-QR first row, full-width compact-item tree then records; retain QR and record controls while ticket 03 migrates them.
- [ ] Verify malformed escapes, duplicate/empty/flag fields, nested hash routes, base suffix preservation, inline submit/cancel/focus, all insert/drop targets and rejection, confirmed deletion, depth-correct variable encoding and copying.
- [ ] Current/legacy/bare share hashes restore, editing replaces history after debounce and clearing removes the share hash.
- [ ] Example remains explicit.

## Requirement acceptance checklist

- [ ] **U01** — As a developer, I want protocols, paths, query text, nested encoded URLs and hash routes parsed while preserving repeated keys, flags, empty values and malformed-escape tolerance, so that real links remain editable.
- [ ] **U02** — As a developer, I want a recursive editable parameter/hash tree with each URL's base, so that nested structure stays visible.
- [ ] **U03** — As a developer, I want to edit keys, ordinary values and root/nested bases with correct subtree rebuilding and suffix preservation, so that edits retain unrelated parameters.
- [ ] **U04** — As a developer, I want Enter/blur submission, Escape cancellation, unchanged-edit preservation and initial focus on a new key, so that inline editing remains predictable.
- [ ] **U05** — As a developer, I want root insertion, insertion after an ordinary field and insertion inside a nested URL, so that I can add fields at the intended level.
- [ ] **U06** — As a developer, I want confirmation before deleting a field or URL subtree, so that cancellation preserves my current input.
- [ ] **U07** — As a developer, I want to move key/hash nodes and complete subtrees between valid targets while invalid/self/descendant drops are rejected, so that restructuring is safe.
- [ ] **U08** — As a developer, I want separate original-input and serialized root/subtree copying with feedback, so that I can choose the appropriate complete representation.
- [ ] **U09** — As a developer, I want valid `$$name` variables to generate highlighted JavaScript template code with correct encoding depth and copying, so that nested URL templates remain usable.
- [ ] **U10** — As a tool user, I want to explicitly load the nested OAuth example, so that I can explore the tool without replacing an empty start automatically.
- [ ] **U24** — As a developer, I want current, old-text and bare share hashes restored and debounced replacement/clearing preserved, so that share links work without adding browser-history entries while typing.
- [ ] **U25** — As a tool user, I want empty input, tree and QR states when no share content exists, so that the tool starts honestly and the example remains optional.
- [ ] **D05** — As a URL-tool user, I want equal-height input and QR panels on the top row, a full-width tree below and full-width records after that, so that each area has a clear place.
- [ ] **D06** — As a URL-tool user, I want close vertical spacing between tree items with wrapping and editable fields preserved, so that long parameter trees remain readable and efficient.

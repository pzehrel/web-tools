# 02: URL 递归编辑与分享链接往返

**主要需求:** U01–U10、U24–U25、D05–D06。

## 验收条件

- [ ] 首行输入与居中二维码等高，下面依次为整行紧凑树和记录；03 迁移前保留二维码与记录控件。
- [ ] 验证错误转义、重复／空值／标记参数、嵌套 hash 路由、基址后缀保留、行内提交／取消／焦点、所有插入与拖放目标及拒绝规则、删除确认、按深度编码的变量和复制。
- [ ] 当前／旧文本／裸分享 hash 均可恢复，编辑防抖替换历史，清空移除分享 hash。
- [ ] 示例通过明确操作加载。

## 需求验收清单

- [ ] **U01** — 作为开发者，我希望解析协议、路径、查询文本、嵌套编码 URL 和 hash 路由，并保留重复 key、无值字段、空值及错误转义容错，以便编辑真实链接。
- [ ] **U02** — 作为开发者，我希望使用显示各 URL base 的递归可编辑参数／hash 树，以便看清嵌套结构。
- [ ] **U03** — 作为开发者，我希望编辑 key、普通 value、根及嵌套 base 时正确重建子树并保留后缀，以便保留无关参数。
- [ ] **U04** — 作为开发者，我希望 Enter／失焦提交、Escape 取消、无变化编辑不改写内容，并在新增 key 时自动聚焦，以便行内编辑可预期。
- [ ] **U05** — 作为开发者，我希望在根级新增、普通字段之后插入，以及嵌套 URL 内新增，以便在正确层级添加字段。
- [ ] **U06** — 作为开发者，我希望删除字段或 URL 子树前确认，以便取消时保留当前输入。
- [ ] **U07** — 作为开发者，我希望将 key／hash 节点和整棵子树移到有效目标，并拒绝无效、自身或后代投放，以便安全调整结构。
- [ ] **U08** — 作为开发者，我希望分别复制原始输入和序列化的根／子树 URL 并获得反馈，以便选择合适的完整表示。
- [ ] **U09** — 作为开发者，我希望合法的 `$$name` 变量生成带高亮、编码层数正确且可复制的 JavaScript 模板代码，以便复用嵌套 URL 模板。
- [ ] **U10** — 作为工具用户，我希望明确载入嵌套 OAuth 示例，以便在探索工具时不自动替换初始空态。
- [ ] **U24** — 作为开发者，我希望恢复当前、旧 text 和裸分享 hash，保留防抖替换地址与清空，以便分享链接有效且打字不增加历史条目。
- [ ] **U25** — 作为工具用户，我希望没有分享内容时输入、树与二维码均显示空态，以便诚实地开始工作，并自主使用示例。
- [ ] **D05** — 作为 URL 工具用户，我希望顶部输入区和二维码区同排等高，下方参数树独占整行，再下方记录独占整行，以便各区域位置明确。
- [ ] **D06** — 作为 URL 工具用户，我希望树 item 上下间距紧凑，并保留换行与编辑字段，以便高效阅读长参数树。

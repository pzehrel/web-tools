# Mermaid parsing, rendering, and round-trip boundaries

Research date: 2026-10-20. Decision context: [Mermaid editor: investigate parsing, rendering, and round-trip fidelity](https://github.com/pzehrel/web-tools/issues/16), within [the Mermaid editor wayfinding map](https://github.com/pzehrel/web-tools/issues/15).

This report records facts for later decisions. It does not choose the editor's authoritative model, visual-editing coverage, or import policy. No product code or dependencies were changed, and no rendering experiment was performed.

## Evidence baseline

The inspected upstream is **Mermaid 12.2.0**, tag `mermaid@12.2.0`, resolved through GitHub's tag API to commit **`1fb7869866dd619168d840291c9c54b4f129758b`**. Source links below are immutable. Its repository contains `@mermaid-js/parser` **2.0.1**. These are researched versions, not a dependency recommendation. The current official documentation also identifies itself as 12.2.0. [Mermaid package](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/package.json), [parser package](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/parser/package.json), [official usage](https://mermaid.js.org/config/usage.html).

Evidence labels:

- **Confirmed:** directly visible in official documentation or inspected source.
- **Inference:** consequence of the evidence, requiring a product decision or implementation proof.
- **Unverified:** explicitly left for a bounded integration experiment.

## Public APIs versus implementation access

| Capability | Confirmed API or source behavior | Boundary |
| --- | --- | --- |
| Validate Mermaid text | `await mermaid.parse(text, options)` returns `ParseResult`, containing `diagramType` and extracted `config`; invalid text throws, or returns `false` with `suppressErrors: true`. | The return value is **not a graph AST**, node list, or source map. |
| Render text | `await mermaid.render(id, text, container?)` returns `svg`, `diagramType`, and optional `bindFunctions`. | It returns presentation output, not an editable source model. |
| Detect diagram type | `mermaid.detectType` identifies a registered diagram type; detection can fail. | Type detection is not syntax validation or an editability check. |
| Access internal diagram DB | `mermaid.mermaidAPI.getDiagramFromText` returns a `Diagram` with its diagram-specific DB/parser/renderer. | The enclosing `mermaidAPI` property is explicitly `@internal` and `@deprecated`; comments direct consumers to public `parse`/`render`. Export visibility does not make this a stable editor contract. |
| Parse selected languages into AST | `@mermaid-js/parser` exports asynchronous `parse(diagramType, text)` and AST types. | Its enumerated supported types include `architecture`, but **not `flowchart`**, sequence, class, or state. It is not a universal replacement for Mermaid's diagram parsers. |

Sources: [public types](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/types.ts#L94-L154), [Mermaid interface and queue](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/mermaid.ts#L309-L457), [internal API](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/mermaidAPI.ts#L744-L780), [parser overloads and error behavior](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/parser/src/parse.ts), [parser exports](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/parser/src/index.ts).

**Confirmed:** no source-code serializer or lossless parse/modify/print API appears in the inspected `Mermaid` interface or parser package entry points. This is a bounded API inspection, not proof that no third-party tool exists. **Inference:** source generation and any source-preserving patch layer require work beyond calling public `mermaid.parse` and `render`.

## Flowchart model and identity

**Confirmed:** flowcharts use a Jison grammar whose actions mutate `FlowDB`. Its getters expose vertices, edges, subgraphs, classes, and direction. The inspected `FlowVertex`, `FlowEdge`, and `FlowSubGraph` types contain no source token/range fields. Grammar actions pass semantic values to the DB, not a retained concrete syntax tree. [Grammar](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/diagrams/flowchart/parser/flow.jison#L367-L512), [DB getters](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/diagrams/flowchart/flowDb.ts#L588-L613), [model types](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/diagrams/flowchart/types.ts).

- A source node ID keys a `Map`; repeated declarations update the same vertex. Labels are trimmed, sanitized, and may have surrounding quotes removed. The last supplied label replaces the previous one. A renderer DOM ID is separately constructed from a prefix, node ID, and counter, and may gain a diagram prefix. Neither the DOM ID nor a visible label is a substitute for source identity. [Node handling](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/diagrams/flowchart/flowDb.ts#L97-L275).
- Edges have optional explicit IDs (`e1@-->`) and generated IDs otherwise. Generated IDs depend on endpoints and existing parallel edges. A repeated explicit ID is not assigned twice. Grouped links expand into several edges; only one receives the explicit ID. Editing or reordering can therefore affect identity if the editor relies on generated values. [Edge handling](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/diagrams/flowchart/flowDb.ts#L279-L374).
- Subgraphs retain IDs, titles, members, direction, classes, and optional metadata. Missing IDs are generated. Repeated subgraph IDs merge members into the first declaration. Source declaration boundaries are not retained in that model. [Subgraph handling](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/diagrams/flowchart/flowDb.ts#L636-L761).

**Inference:** this DB can inform a semantic adapter under a pinned-version strategy, but cannot by itself reconstruct the original text. It also needs copying/ownership discipline: `Diagram.fromText` obtains a registered diagram DB and clears it before parsing; it is not a documented immutable editor document. [Diagram lifecycle](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/Diagram.ts#L17-L112).

## Fidelity and syntax boundaries

For this investigation, **text fidelity** means retaining the source string, including comments, whitespace, quoting, declaration order, and unsupported constructs. **Semantic fidelity** means retaining the intended nodes, edges, groups, labels, direction, styling, interactions, and configuration. These are separate acceptance criteria; identical appearance is weaker than either.

| Input feature | Confirmed behavior | Consequence for a later editor decision |
| --- | --- | --- |
| Comments, line endings, frontmatter, directives | Preprocessing retains an internal raw string but normalizes CRLF, extracts YAML/frontmatter and directives, and constructs comment-stripped code. Some diagram implementations opt into comment-preserving parsing. | Internal raw storage is not a public lossless editing API. Retain user source separately if exact text must survive. |
| Source positions | Generic internal `DiagramCode` supports comment-preserving text and a frontmatter line offset. FlowDB does not opt into these position hooks; its flow model has no ranges. | New position support elsewhere in Mermaid must not be advertised as flowchart source mapping. |
| Multiple declarations / chains / grouped edges | The grammar and DB reduce these to merged nodes and expanded edge records. | Reprinting semantic records changes text shape and may affect order-based behavior. |
| Styles and classes | Grammar accepts `style`, `classDef`, `class`, shorthand classes, and `linkStyle`; edge styling can refer to numeric positions. | Reordering/removing edges may require rewriting index-based style references. Preserving an unknown style line verbatim is insufficient if its target shifts. |
| Links and callbacks | Grammar accepts click statements; FlowDB stores links and registers callbacks subject to security configuration. | “Renderable”, “preserved”, and “enabled” are different capabilities. Editing selection gestures need not enable source-defined callbacks. |
| Extended metadata | Flowchart supports `@{...}` node/edge/subgraph metadata; DB understands selected fields, including image/icon/shape, edge animation, and collapsed subgraphs. | Unknown metadata cannot be assumed to survive a DB-to-source conversion. |
| Invalid or newer syntax | Parse errors reject or become `false`; public parse does not return a partial editable graph. | Retaining invalid text and the last valid preview requires application state; it is not supplied by parse. |
| Other diagram kinds | Mermaid uses different DBs, grammars, and rendering implementations. | Broad rendering support does not establish broad visual-editing support. |

Sources: [preprocessor](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/preprocess.ts), [source-position hooks](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/diagram-api/types.ts#L15-L87), [flowchart grammar](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/diagrams/flowchart/parser/flow.jison), [FlowDB](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/diagrams/flowchart/flowDb.ts), [parse implementation](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/mermaidAPI.ts#L96-L121).

**Confirmed:** flowcharts support nested subgraphs and links to/from subgraphs. Their documented limitation says a subgraph's local direction is ignored when a member links outside; it inherits the parent direction. This matters for the requested cross-group connections. It should be demonstrated in a pinned-version layout experiment before accepting a placement promise. [Official flowchart source documentation](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/docs/syntax/flowchart.md#L1015-L1057).

**Confirmed:** ordinary flowchart model types have no persisted arbitrary `x`/`y` node positions. The `pos` metadata field in `FlowVertex` means image/icon label placement (`t`/`b`), not canvas coordinates. **Inference:** a drag-position promise needs an explicit relationship between editor layout state and Mermaid's automatic layout; moving rendered SVG elements alone does not change Mermaid source.

### “Architecture diagram” has two meanings

An architectural drawing made from **flowchart** nodes, edges, and subgraphs is a use case. Mermaid's **`architecture-beta`** is a separate language, with groups, services, junctions, and port-qualified edges. It uses `@mermaid-js/parser`'s `architecture` AST and a separate DB/renderer. Its AST availability does not solve flowchart import. The user's “architecture diagrams first” does **not** resolve which meaning belongs in the first visual-editing release. [Architecture grammar](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/parser/src/language/architecture/architecture.langium), [architecture adapter](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/diagrams/architecture/architectureParser.ts), [official architecture guide](https://mermaid.js.org/syntax/architecture.html).

**Unverified:** the selected parser package's exported Langium AST/CST location behavior, preservation of hidden tokens/comments, error recovery, and suitability for safe text patches. Its source returns `result.value` and throws if lexer/parser errors exist; no lossless printer is exposed in the inspected entry points. Avoid inferring a complete round-trip editor from the word “AST”.

## Browser rendering, security, and SSG constraints

1. **Confirmed — local runtime:** the documented package can render in a browser without a rendering backend. Source `render` nevertheless accesses `document.body`, creates SVG/style/temporary elements, and executes layout. It cannot render during this project's Node SSG pass without an appropriate DOM environment. The entry point guards one load-event registration with `typeof document`; that guard is not proof that every import path is SSR-safe. **Inference:** client-only initialization/rendering, deterministic SSG fallback, and a verified dynamic-import boundary are integration candidates. [Render lifecycle](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/mermaidAPI.ts#L480-L680), [entry-point load handling](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/mermaid.ts#L270-L290).
2. **Confirmed — asynchronous queue:** public `mermaid.parse` and `render` share a serial execution queue. They have no cancellation argument in the inspected signatures. **Inference:** rapid input can queue obsolete work; a document/revision token should determine whether a resolved preview may be applied. Debouncing and queue coalescing need measurement. Do not bypass the queue through internal API calls merely to gain concurrency. [Queue implementation](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/mermaid.ts#L309-L420).
3. **Confirmed — untrusted input:** default `securityLevel` is `strict`; configuration also offers `loose`, `antiscript`, and `sandbox`. `secure` keys, including `securityLevel`, `maxTextSize`, and `maxEdges`, can only be changed through host initialization. Rendering sanitizes generated SVG with DOMPurify unless loose mode is active, and sandbox mode follows a separate iframe path. **Inference:** imported source should not choose host trust policy. Sandbox mode's interaction and export tradeoffs need validation; sanitization is not proof of network isolation. [Configuration schema](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/schemas/config.schema.yaml#L315-L361), [secure-key filtering](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/config.ts#L228-L272), [SVG sanitization](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/mermaidAPI.ts#L628-L680).
4. **Confirmed — local does not mean offline:** the flowchart image renderer constructs `new Image()`, assigns the imported `node.img` URL, and awaits decoding before producing SVG. External image references can therefore create requests during rendering. Fonts and registered icon loaders can also have host-controlled asset loading. **Inference:** this repository's local-data promise requires an explicit asset/network policy and a browser request check. Bundling Mermaid alone does not establish a no-network guarantee. [Image renderer](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/rendering-util/rendering-elements/shapes/imageSquare.ts#L10-L20), [image syntax](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/docs/syntax/flowchart.md#L650-L681).
5. **Confirmed — limits and errors:** defaults are 50,000 text characters and 500 edges. FlowDB throws on its edge limit. Rendering overlong cleaned text substitutes a limit-message diagram; parsing and rendering are therefore not interchangeable size-policy gates. Syntax/render errors may touch temporary DOM before rejection; `suppressErrorRendering` changes that behavior. **Inference:** the application needs explicit import/complexity boundaries and error-state ownership. [Limits schema](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/schemas/config.schema.yaml#L87-L95), [render size/error paths](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/mermaidAPI.ts#L480-L599), [edge limit](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/diagrams/flowchart/flowDb.ts#L330-L342).
6. **Confirmed — compatibility and license:** Mermaid 12's official usage guide targets ES2024 and Safari 17.4+, and the package requires Node >=22.12.0. The repository's MIT license permits redistribution/modification with its copyright and permission notice. Dependency licenses and any separate assets still need the normal dependency review. [Runtime guide](https://mermaid.js.org/config/usage.html#supported-browsers-and-runtimes), [package engines](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/package.json), [MIT license](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/LICENSE).

The repository's existing `AGENTS.md` also requires explicit route IDs and synchronized `ROUTE_IDS`, client-only storage UI, SEO, and hydration verification. These are future integration constraints; this research adds no route or runtime code.

## Decisions enabled, and bounded validation still needed

The facts support separating four questions: which syntax is renderable, which is representable in an editor model, which operations preserve semantics, and which operations preserve original text. They do not settle the answers for this product.

Before implementation commitments, later tickets can bound these experiments:

- Pick a supported syntax subset and use adversarial fixtures: repeated declarations, parallel/identified edges, grouped chains, nested/cross-linked subgraphs, Unicode/escaped labels, markdown/HTML labels, comments, CRLF, YAML/directives, classes/styles, callbacks, metadata, invalid and unsupported syntax. Check source preservation separately from semantic preservation.
- If internal FlowDB access remains a candidate, prove pinned-version ownership and snapshot behavior across consecutive parses; record migration cost. If source patching remains a candidate, prove exact source ranges and edits for that subset rather than inferring them from SVG.
- Check actual target Safari, production Vite/SSG build, hydration, font readiness, SVG export, and rapid-edit/unmount races. No browser render, performance figure, or universal SSR compatibility is claimed here.
- Inspect network requests for hostile external image/icon/font references and verify the chosen trust policy. Measure large graphs and deliberately slow/failed asset loading. Do not claim strict mode prevents all requests.

These are validation needs and unresolved product/architecture choices. They do not block closing this factual research ticket.

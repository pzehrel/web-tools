# Web 全站 UI 重设计决策地图

Labels: wayfinder:map
Status: open

## Destination

形成一套经用户确认、足以进入实现的 Web UI 重设计方案，本阶段覆盖首页、四个公开工具页及共享组件，同时重做操作体验与视觉；隐藏工具暂缓。
地图完成时，目标任务、信息架构、视觉方向、工作台交互、组件规则和验收标准均有明确结论；正式产品实现另行开展。

## Notes

- 2026-10-20：用户调用 to-spec 并确认以真实产品页面为主的测试边界；后续实施交接依据为[实施规格](../web-ui-redesign-implementation/spec.zh-CN.md)，状态 ready-for-agent。该规格汇总已确认的工作台、共享交互与验收要求；本轮不额外更改其他规划票状态。
- 用户于 2026-10-18 确认：先定完整方案；操作体验与视觉都重做；现有视觉规范可以整体推翻。
- 保留亮色、暗色和跟随系统模式、语义颜色令牌、现有功能及浏览器本地处理机制。规划限定 `apps/web`，不扩展为后端或管理端项目。
- 内容约束：界面不强调本地处理、设备端数据或数据不上传；具体反馈记录在视觉方向票。此约束不改变处理机制。
- 后续重设计与实现以[全工具功能保留基线](../../docs/ui-redesign/README.zh-CN.md)逐项核对；原型缺失不缩小功能范围。各工具的行为与验收依据在该清单维护；扩展前覆盖状态保留为历史快照，最新界面位置与验证边界见[当前完整功能原型](../../docs/ui-redesign/prototype-current.zh-CN.md)。
- 用户于 2026-10-19 明确“隐藏的工具先不做”：当前阶段仅推进 URL 与二维码、帧动画、Lottie 预览、点九图四个公开工具，以及首页和共享组件。CSS 扫光、字体工具箱暂不继续设计或评审，已有原型和功能基线保留；恢复推进需用户后续明确。
- 用户于 2026-10-20 明确隐藏工具的全部界面入口：CSS 扫光与字体工具箱不出现在首页或工具切换菜单。现有工具代码、功能基线与直达路由保留。
- `AGENTS.md` 描述新粗野主义，`docs/DESIGN.md` 描述瑞士极简，当前实现也存在差异。用户于 2026-10-20 确认 F 原型评审完成；最终方案必须说明哪些旧规范应被替代，规划阶段不直接改写现行规范。
- 工作区已有用户未提交改动。以当前工作区为现状证据，保留这些改动；不自动提交、回滚或在本轮改造产品代码。
- 每次继续先读本地图，再查询可领取的子票。使用 wayfinder；对话票使用 grilling 与 domain-modeling；原型票使用 prototype。涉及外部知识时才新增 research 票，由研究子代理处理。
- 使用中文和简洁完整的句子。文档、评审和对话引用票的标题及链接，不用裸编号替代名称。
- 已确认的任务与设备基准见 Decisions so far 对应票；后续原型必须采用同一组任务比较，不另行假定使用场景。
- 本地 tracker：本文件是唯一地图；`issues/` 中一文件一票，文件名数字是本地身份。票只有 `wayfinder:*` 标签；`Status: open`、`claimed`、`resolved` 分别表示待领取、已领取、已解决。
- `Blocked by: none` 表示无前置票；否则列出票文件的数字身份。前置票全部 `resolved` 且本票 `open`、`Assignee: unassigned` 时才进入 frontier，按文件编号排序。领取时先写 `Status: claimed` 和实际负责人，解决时在 `## Comments` 追加带日期的 `### Resolution`，并追加 `## Answer`、设为 `resolved`，再给地图添加摘要链接。
- 建图轮只整理决策，不解决人工参与的票。后续每轮最多解决一张票，研究票除外。

## Decisions so far

- [用可比较的原型选择全站视觉方向](issues/03-visual-direction.md#answer)：当前 F 原型评审完成，保留首页、四个公开工具及共享语义色／控件决策；隐藏工具暂缓，正式实现与运行验收另行开展。

- [确定重设计服务的核心任务与设备边界](issues/01-target-workflows.md#answer)：已确认核心人群、三类原型任务、操作链路的审查重点和桌面／手机边界。
- [确定首页目录与工具之间的导航方式](issues/02-information-architecture.md#answer)：首页直达工具，页头支持返回与切换，统一使用“URL 与二维码”；入口样式留给原型比较。
- [研究同类工具网站可借鉴的界面模式](issues/07-comparable-tool-sites.md#answer)：六站第一方页面与截图已核查，按工具任务选用入口、文本结果与画布模式，作为新候选的依据。
- [梳理全部工具的功能保留基线与原型覆盖](issues/08-function-preservation-baseline.md#answer)：已建立六工具与共享行为的逐项源码基线，明确 F 覆盖和缺口；后续 UI 设计保留全部既有能力。

## Not yet specified

- 各工具在共同工作台规则下需要哪些特例，哪些应保留独有布局；待代表原型暴露具体差异后逐项立票。
- 导入、空白、处理中、失败、有结果、恢复历史等状态的具体呈现，以及是否需要新增状态；待主要任务和交互骨架明确。
- 已确认的手机核心操作如何落实为具体布局与触屏交互；等待工作台模型明确。精细切片和多帧排序的设备优先级已在核心任务票中确定。
- 最终方案如何组织到仓库文档、如何替代冲突规范，以及实现工作的拆分粒度；待前面的设计决定稳定。

## Out of scope

- 本阶段继续设计或评审 CSS 扫光、字体工具箱；用户已明确暂缓。已有工具、原型与功能基线保留，不删除能力或自动公开入口。

- 本地图交付正式产品 UI 代码、生产部署或发版。原型仅用于检验设计问题，不自动成为产品实现。
- 新增工具、扩展现有工具的核心能力、删除既有功能，或自动重新公开隐藏工具。
- 后端、管理端、账号系统、云端同步、数据库迁移、桌面封装及技术栈迁移。

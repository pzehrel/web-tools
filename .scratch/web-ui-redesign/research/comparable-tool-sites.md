# 同类工具网站 UI 参考研究

研究日期：2026-10-18。对应决策票：[研究同类工具网站可借鉴的界面模式](../issues/07-comparable-tool-sites.md)。

本报告提供下一轮原型的证据，不替用户决定审美方向。只研究已有功能的组织与呈现；本项目仍为四个公开工具，首页直达、页头返回与切换、桌面优先及手机核心可用。界面不加入本地处理、设备数据或不上传等宣传。

## 结论

最有用的参照是 **iLoveIMG 的入口与状态切换、IT Tools 的输入结果对应、SVGOMG / Squoosh 的画布空间分配**。三类模式应按任务采用，不能把所有工具硬塞进同一个三栏模板。

首页可以参考 iLoveIMG 的直接功能入口，删去大标题宣传区与分类筛选，只保留四个清楚的工具入口。图像类工作页参考 SVGOMG：主要面积归画布，参数靠边，导出与结果就近；URL 类参考 IT Tools：输入在前，结果逐项对应，复制贴着结果。以上是待原型检验的设计推断，尚未成为已确认方案。

## 证据与边界

- **页面事实**：第一方页面文字、可访问性快照或官方说明能核实的项目。
- **界面观察**：实际浏览器打开后的截图与操作所见，不由抓取文本推断外观。
- **设计推断**：研究者对本项目的应用建议，与原站已存在的行为分开记录。

工具集合站按 1280×720 桌面视口观察；Squoosh / SVGOMG 另有桌面截图，SVGOMG 补充 390px 手机视口。研究使用官方示例及自制的 320×200 简单 SVG，没有使用真实用户文件。只验证所述状态与布局，没有完成所有站点的处理、下载、暗色或移动端流程。抓取页面可能包含未显示的隐藏状态，因此以实际截图判定当前界面。

## 第一方参考

### iLoveIMG：直接选工具，导入后再展开工作区

**事实与观察**：[首页](https://www.iloveimg.com/)是图标、工具名、简短用途组成的卡片网格；页头也能换工具。[调整尺寸](https://www.iloveimg.com/resize-image)空态集中在选择按钮与拖入说明。导入自制 SVG 后，内容变成左侧素材区、右侧固定参数面板，主操作靠底；缩略项下显示输入及目标尺寸。本次 SVG 缩略图未绘出，不能据此判断图片预览质量。

**推断**：借鉴清楚入口与导入前后不同密度；四工具不需要分类标签、登录或大宣传区。不要照搬其文件上传机制、云盘入口及批量功能。

截图：[首页](screenshots/iloveimg-home.png)、[空态](screenshots/iloveimg-resize-empty.png)、[导入后](screenshots/iloveimg-resize-loaded.png)。

### IT Tools：输入与结构化结果放在同一阅读轴

**事实与观察**：[首页](https://it-tools.tech/)有大量工具卡片，左侧是分类导航，顶栏有搜索。[URL parser](https://it-tools.tech/url-parser)在居中主栏先放一条 URL 输入，下方按协议、域名、路径等逐行显示结果，每行就近提供复制。首屏已有示例结果，用户无需先读操作教程。

**推断**：适合本项目 URL 与二维码中的文本解析部分，保留清楚的字段对应和就近复制；不照搬面向大量工具的长侧栏、收藏、搜索、赞助块，也不据此新增字段或功能。

截图：[首页](screenshots/it-tools-home.png)、[URL parser](screenshots/it-tools-url.png)。

### 10015 Tools：输入、可视结果与下载的顺序明确

**事实与观察**：[首页](https://10015.io/)首屏为品牌介绍、探索按钮和扩展入口，工具集合在后。[二维码页](https://10015.io/tools/qr-code-generator)上方是标题和辅助操作，下面为单行文本输入、重置及大二维码区域；页面文字说明输入变化后生成二维码，并提供下载。观察时标题和输入之间存在未正常加载的占位块，不认定其具体内容。

**推断**：可以借鉴简单的输入到预览顺序；不采用宣传首屏、复杂分类、收藏、长解释文章或占位块，避免高频用户先滚动再操作。

截图：[首页](screenshots/10015-home.png)、[二维码页](screenshots/10015-qr.png)。

### TinyWow：仅作低优先参照

**事实与观察**：[首页](https://tinywow.com/)有大标题、搜索框、五类入口及统计区。[调整尺寸](https://tinywow.com/image/resize)空态是宽白色容器，中央放选择文件按钮、拖入说明及云盘入口。未导入素材，未核查编辑及输出状态。页面抓取文本包含额度和定价状态，但截图未显示，不能说当前访客已被限制。

**推断**：只取主操作容易识别这一点；本项目不需要大分类、统计证明、云盘、额度或订阅流程。其首页体量不适合四工具。

截图：[首页](screenshots/tinywow-home.png)、[工具空态](screenshots/tinywow-resize.png)。

### Squoosh：把工作面积交给素材

**事实与观察**：[首页](https://squoosh.app/)可拖入、粘贴或选用四个官方示例。选示例进入[编辑器](https://squoosh.app/editor)后，深色画布铺满视口，中央为对比拖杆，下缘有缩放；右下是编辑和压缩控制区，常用质量滑杆可见，高级设置折叠；下载和体积信息靠近画布下缘。截图中一侧仍在编码，不宣称导出已通过。

**推断**：借鉴画布优先、常用参数直接可见、高级项展开、结果与导出相邻。不要复制对比压缩功能、整套编码选项及首页宣传风格。

截图：[首页](screenshots/squoosh-home.png)、[编辑器](screenshots/squoosh-editor.png)。

### SVGOMG：桌面并排，手机上下组织

**事实与观察**：[官方页面](https://jakearchibald.github.io/svgomg/)打开 Demo 后，顶栏为 Image / Markup，主体是大棋盘画布，右侧为白色长参数面板；复制、下载和体积结果贴画布边缘。390px 下变为上画布、下参数，结果与操作条处在两者交界。此站具备细分优化开关，但不能推断本项目也需要这些开关。

**推断**：这比“全部操作塞进卡片”更适合点九图、Lottie 和帧动画的预览区域；手机可参考上下重排，但精细切片和多帧排序仍依既定桌面边界。不能照搬 SVG 优化能力与全部选项。

截图：[桌面](screenshots/svgomg-editor.png)、[手机](screenshots/svgomg-mobile.png)。

## 转为下一轮原型的约束

| 本项目区域 | 有依据的尝试 | 不直接照搬 |
| --- | --- | --- |
| 首页 | 四个清楚的工具入口；简短用途；低干扰页头 | 大 Hero、搜索、分类、计数、信任背书和宣传标识 |
| 页头 | 首页返回和当前工具切换；亮暗主题 | 长工具侧栏、会员、云盘和复杂多级菜单 |
| URL 与二维码 | 输入与结果在同一阅读轴；复制靠近目标；二维码与文字结果分清 | 未有的新解析字段、二维码新参数或转换能力 |
| 点九图、Lottie | 画布占主要区域；相关参数靠边；状态和导出靠近结果 | 每个工具一律三栏；把全部功能藏进分步页 |
| 帧动画 | 保留其必要素材与帧操作区，再确定画布及参数位置 | 因外部产品有批量卡片就增加批量能力 |
| 手机 | 画布与主要参数上下重排；核心导入、预览、基本参数和导出可达 | 声称外站全部移动流程已验证；压缩桌面多栏强行塞入 |

原型应先用同一个首页、点九图和 URL 任务检验布局；帧动画补充验证多素材。下一轮可尝试去掉大外壳圆角、巨型编号、装饰预览与阶段切换，以正常字号的功能入口、明确导入空态和真正的画布空间形成一个连贯候选。这是本项目的设计推断，并非声称参考站证明这些样式普遍更好。

正文与控件标签应维持正常阅读尺度，不能靠大量 11px 小标签制造“专业感”。作为观察基准，主研究会话测得 SVGOMG 桌面顶栏约 48px，页面 h1 为 16px、分组标题约 14.4px；它仍通过明确分组和空间比例保持密度，而非所有文字一律缩小。该测量仅代表本次页面状态，不是本项目已确定的字号规范。

视觉仍需用户亲自评审，本站截图只能帮助校准，不意味着用户已偏好任何一个参考站。最终需要确认的是实际密度、画布比例、控件形态及明暗主题，而非再给抽象风格起名字。

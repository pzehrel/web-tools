> 2026-10-19 用户决定：本次布局未采用，用户认为前一版更好看。已恢复调整前的布局：整行输入位于参数树和二维码／记录列上方。下方调整表仅作历史记录，功能缺口核查继续有效。未采用的原型源码不再保留，本报告保留决定与核查边界。

核查日期为 2026-10-19，依据当前产品源码、[25 项功能保留基线](features/url.zh-CN.md)和[当前原型映射](prototype-current.zh-CN.md)。本轮属于源码核查与原型调整，不是浏览器验收。

## 自评与调整

| 调整前的观察                                               | 调整后的界面                                                                                             |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 输入横跨整页，使参数树与二维码列分离，并占用两列顶部空间。 | 输入与树合并为主编辑列，264px 侧列并排放置二维码与记录。                                                 |
| 长参数树与记录共用页面滚动。                               | 桌面参数树与记录列表独立滚动。手机纵向排列完整区域，内部滚动有高度限制。                                 |
| 点击二维码图片放大，点击周边区域却打开图片识别。           | 原生按钮负责放大二维码，独立且有文字的识别图片按钮打开选择器；拖入与粘贴图片继续支持。                   |
| 根级新增是小图标，原文复制与序列化复制不易区分。           | 根级新增在树工具行提供文字入口。输入复制明确为“复制原文”，根复制明确为完整的序列化 URL。嵌套行操作保留。 |
| 变量代码没有标题，复制入口却在树标题处。                   | 条件显示的代码块增加标题和相邻的复制入口。变量生成与编码方式不变。                                       |
| 二维码识别与导出错误出现在文本输入附近。                   | 对应错误移至二维码区，并使用 alert 语义。空白与纯文本的参数树说明继续保留。                              |

递归可编辑树继续是主要结构化视图，没有增加平面的“解析结果”摘要。选中记录仍须明确更新；保存始终新增快照。原生二维码按钮也支持 Enter 与空格。

# Frame animation and Lottie preservation baseline

> **Historical audit snapshot:** Coverage states and gaps below were recorded before the full-function expansion and do not describe the current F. Existing behavior and preservation criteria remain valid. See the [current full-function prototype](../prototype-current.md) for the latest per-ID UI mapping and validation boundaries.
> [Baseline index](../README.md) · [简体中文](motion.zh-CN.md)

2026-10-18. Source audit of the current working tree; browser interactions and exported files were not runtime-tested in this audit.

This inventory lists user capabilities implemented in the current source. Every row is required to survive the production UI redesign; prototype absence does not authorize removal. The new F floating layout does not substitute for existing capabilities.

Status: `covered` = prototype implements the row (not runtime acceptance); `partial` = incomplete or reduced behavior; `missing` = no F counterpart; `legacy-only` = F opens the existing page, where the capability remains available but has not been redesigned.

All Lottie rows are `legacy-only`: [ToolLink](../../../apps/web/src/ui-redesign.prototype.tsx#L108) links directly to `/tools/lottie-preview` without variant; this is not F redesign coverage.

## Boundaries and verification

- Production frame animation downloads PNG sprites; CSS/Less/SCSS are copyable styles. Its internal ZIP archive stores records and is not a user ZIP export. GIF/WebM/APNG animation exports are not claimed as existing capabilities.
- Sequence reordering uses HTML drag events. Native phone touch reordering has not been confirmed and is not accepted here. Touch canvas pan/pinch is implemented in shared hooks.
- Production frame animation filters failed image decodes without a dedicated per-file failure message; detailed per-file error reporting is not claimed. Production Lottie ZIP export requires an atlas result; original-package download with optimization disabled is not claimed.
- Evidence here is source code. Complete new-UI acceptance still requires real imports, actual outputs, saved-record restoration, mouse/touch and light/dark themes.

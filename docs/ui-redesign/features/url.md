# URL and QR code: functional baseline and F coverage

> **Historical audit snapshot:** Coverage states and gaps below were recorded before the full-function expansion and do not describe the current F. Existing behavior and preservation criteria remain valid. See the [current full-function prototype](../prototype-current.md) for the latest per-ID UI mapping and validation boundaries.
> [Baseline index](../README.md) · [简体中文](url.zh-CN.md)

Audited on 2026-10-18 against the current working tree, including uncommitted product changes. This is a source audit, not a new full browser certification. `C` = covered, `P` = partial, `M` = missing. Coverage describes executable behavior, not final design approval. Every existing capability below remains in scope for the redesigned product.

## Evidence

- [Product UI](../../../apps/web/src/tools/url-parser/index.tsx): `EditableText`, `ParamRow`, `ParamTree`, `RecordPreviewTip`, `QrDownloadButton`, `UrlParserTool`.
- [Parsing and tree mutations](../../../apps/web/src/tools/url-parser/url-tree.ts): `parseUrl`, `serializeUrl`, `mergeBaseEdit`, `canMoveNode`, `moveNode`; recursion is bounded by `MAX_DEPTH = 8`.
- [Variable code generation](../../../apps/web/src/tools/url-parser/url-code.ts), [QR codec](../../../apps/web/src/tools/url-parser/qr-codec.ts), [combined image](../../../apps/web/src/tools/url-parser/qr-preview-image.ts), [records](../../../apps/web/src/tools/url-parser/url-records.ts), [hash synchronization](../../../apps/web/src/lib/hash-param.ts).
- [F UI](../../../apps/web/src/ui-redesign-url.prototype.tsx): copies the product interaction flow and reuses its parsing, code generation, codec and combined-image modules. Its `useUrlRecords` is a memory-only substitute; hash effects are absent. Parent [F routing](../../../apps/web/src/ui-redesign.prototype.tsx): `VariantF` mounts this component for `/tools/url-qrcode`.

## Boundary and verification

The new design has no separate “parsed results” panel: the editable tree is the primary structured view. Removing that added prototype panel does not authorize removing parsing, variables, QR conversion or records.

Prior prototype browser checks exercised nested edits, insertion/focus, drag nesting, variable copy, record operations in memory, QR detail, both downloads, image recognition and mobile tree editing. They do not prove persistent records, legacy migration or hash compatibility, which F does not implement. Source parity is not a claim that all parser edge cases or every browser were re-tested in this inventory pass.

# UI 重设计：现有功能保留基线

> **历史审计快照：**以下覆盖状态及缺口记录于完整功能扩展之前，不代表当前 F。现有功能与保留验收仍有效；最新逐项界面映射与验证边界见[当前完整功能原型](prototype-current.zh-CN.md)。
> [English](README.md)

新 UI 必须保留当前产品全部用户可见能力。在此审计时点 F 是部分可操作的设计研究，原型遗漏不会缩小正式实现范围。本清单是后续 UI 设计和实现的功能依据。布局、组件样式、标签可以改变；删除或收窄既有能力需要用户明确决定。

## 原型的主要缺口

- **URL／二维码：**记录操作在内存模拟，缺少持久记录、旧数据迁移和 hash 分享。F 默认载入示例，与产品初始空白不同。树编辑、变量、二维码互转和两种下载已接入。
- **帧动画：**ZIP／目录导入、追加／自然排序、勾选与拖排、透明边裁剪、播放范围／方向／有限循环、完整 FPS／时长控件、原分辨率可配置网格精灵图、CSS／Less／SCSS 生成及项目持久化均未覆盖或缩水。产品导出 PNG 精灵图与动画代码，本审计不声称已有 GIF／视频下载功能。
- **点九图：**尚未复现切线拖动／键盘与按源图约束、自动分析、独立宽度、outset、fill 开关、双轴 repeat、中心裁剪／裁剪 PNG、预览独立平移缩放、完整八向缩边及记录。产品已有预览调整尺寸能力；F 的浮动摆放属于布局提案，不是新增的既有能力。实际生成器目前仅提供 CSS 分开写／简写，不能假定有 Tailwind 或已启用的 SCSS／Less 导出。
- **Lottie：**20 组功能全部仍在原 UI：项目导入、双播放库／双渲染器、播放／适配、图集优化全部选项、动态素材排除、资源对比、图集查看、优化 ZIP 导出和项目持久化。
- **CSS 扫光：**四种预览形态、蒙版图片输入、触发／方向、五项动效参数、预设／重播／重置、CSS＋HTML 生成／复制和减少动态效果，均在 F 之外。
- **字体工具箱：**导入／预览／字符查看／体检／子集化／全量转换／下载流程均在 F 之外。UI 输入支持 TTF／OTF／WOFF／WOFF2，UI 输出支持 WOFF2／WOFF／TTF。不能仅凭引擎类型就认定 OTF 导出流程已存在。
- **共享行为：**跟随系统主题与持久偏好、GitHub 入口、旧路径／独立工具路由兼容、项目连续性、副画布行为及生产 SSG／SEO／网页应用检查，均未覆盖或只部分体现于 F。

## 保留要求与实现验收

1. 每个 `U/F/N/L/C/T/G` ID 都要在新 UI 中有明确位置和操作，包括窄屏访问。允许合并面板、收起高级控件，前提是完整能力仍可访问。
2. 保留输入类型、参数含义和有效范围、多轴／多帧行为、输出格式、文件名／内容语义、键盘／触屏路径及错误／空白／忙碌状态。原型中的常量、禁用或缺失控件不是正式规格。
3. 既有持久记录保留工具身份、载荷、参数和载入行为。存储／UI 改动必须核查旧记录与刷新／重开。原型内存记录不替代产品数据。
4. 实现验证按 ID 对应到可复现检查：UI 位置／状态、代表输入、操作和预期结果。导出要核查文件／代码，不能只看点击或成功提示；查看手势不能改变导出参数。
5. 宣告某工具已完整重设计前，补齐该工具所有部分覆盖／未覆盖／仅旧页缺口，并验证既有功能。确需功能变更时另行记录用户明确决定；原型遗漏永远不等于这种决定。

保留能力不要求复制已知缺陷或过时说法。例如，字体下载文件名与代码不一致只作为详细审计中的现状记录，不作为目标行为；点九图旧元数据／SEO 文案也不能证明某导出器已启用。修正问题仍须保留其对应流程并验证。

[设计决策记录](design-decisions.zh-CN.md)汇总已评审方向。以下文字描述较早的审计边界。用户提出的紧凑组件、默认可见画布、浮动参数／预览和 UI 全面重设计继续有效；F 的确切配色和组件选择仍是提案。新增的平面“解析结果”区已排除，URL 树及交互仍受保护。移除关于设备／本地数据的宣传，不删除数据处理或兼容能力。
